# 📊 Text-to-Insights: 자연어 기반 회계/재무 이상 징후 분석 AI 에이전트

> **비전공자 및 감사 실무자를 위한 자연어 질의 기반 SQL 자동 생성, Read-Only 보안 검증, 단일 막대 시각화 및 AI 감사 브리핑 시스템**

---

## 📌 1. 프로젝트 개요 (Overview)
* **목표:** 복잡한 SQL 문법 없이 자연어 질문만으로 1,000건 규모의 기업 법인카드 전표 DB를 분석하고, 이상 거래(FDS) 패턴을 적발하여 시각화 및 감사 인사이트를 원스톱 제공
* **핵심 타겟 도메인:** 기업 회계 및 디지털 감사(Digital Audit), 내부회계관리제도 이상 거래 모니터링
* **개발 환경:** Google Colab, Python 3.10+
* **기술 스택:**
  * **LLM Engine:** Google Gemini API (`gemini-2.5-flash`)
  * **Database:** DuckDB (In-Memory OLAP SQL Engine)
  * **Visualization:** Plotly Express (`px.bar`)
  * **Interface:** Gradio Web UI

## 🛡️ 3. 핵심 엔지니어링 포인트 (Key Engineering Features)

### 1) 회계 감사 특화 정형 데이터셋 설계 (1,000건)
실제 회계 감사 및 FDS 실무에서 점검하는 4대 이상 징후 시나리오를 가상 데이터로 정밀 라벨링:
* **분할결제(쪼개기) 의심:** 건당 50만 원 전결 규정을 회피하기 위해 동일 일자·가맹점에서 수 분 간격으로 분할 결제한 15쌍(30건) 적발 시나리오
* **심야 결제:** 23시~04시 비업무 시간대 결제 로그 분리
* **주말/휴일 결제:** 업무 외 휴일 법인카드 사용 내역 추적
* **고액/한도 초과:** 접대비 50만 원 이상 또는 100만 원 이상 고액 지출

### 2) 엔터프라이즈급 Read-Only 샌드박스 가드레일
* LLM 생성 쿼리가 데이터베이스의 무결성을 해치지 않도록 사전 정규식 필터(`\b(DROP|DELETE|UPDATE|INSERT|ALTER|TRUNCATE|CREATE)\b`) 적용
* 데이터 변조 시도 감지 시 즉시 차단 메시지를 반환하여 프로덕션 안정성 확보

### 3) Self-Correction(자가 수정) 루프
* 생성된 SQL 실행 중 컬럼명 불일치나 문법 오류 발생 시, 에러 콘텍스트를 프롬프트에 재주입하여 최대 2회 자가 수정을 거쳐 올바른 쿼리를 재작성

### 4) Gradio 멀티스레드 세션 격리 (Troubleshooting)
* **문제:** Gradio 백그라운드 워커 스레드 간 단일 DuckDB 전역 커넥션 공유 시 두 번째 요청부터 세션 락(Lock) 충돌 발생
* **해결:** 요청 단위 컨텍스트 매니저(`with duckdb.connect(...) as local_con`)를 통해 세션 생명주기를 분리하여 동시성 안정성 확보
